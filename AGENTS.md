# Правила для кодинговых агентов

Эти правила применяются к любым кодинговым агентам, работающим в репозитории.

## Перед задачей

1. Прочитай `references/PRD_Agent_Guard.docx`, соответствующую спецификацию задачи и профиль роли: `agents/developer.md` или `agents/tester.md`. Для подготовки защиты также прочитай `references/presentation_template_demo1.pdf`.
2. Если источник недоступен, прямо сообщи об этом; не заменяй его содержание догадками. Если спецификация отсутствует, уточни требования до реализации; новую спецификацию создавай только в рамках поручения.
3. Проверь текущие файлы, состояние Git и активную ветку. Сохраняй полезное существующее содержание и чужие изменения. Если они конфликтуют с задачей, сообщи о конфликте до перезаписи.
4. Отличай факты с источником или результатом проверки, гипотезы, требующие проверки, и проектные решения команды. Утверждения об API в PRD сами по себе не доказывают работоспособность интеграции.

## Ветки и полномочия

Рабочий путь: `features/<имя>/<номер>-<задача>` → проверка другим человеком → `dev` → по завершении итерации `main`.

Меняй файлы только в ветке своей задачи. До изменений убедись, что активная ветка соответствует поручению; если нет — согласуй переход. Не меняй файлы непосредственно в `dev`, `main` или чужой ветке задачи.

Агент может изменять файлы в пределах задачи и запускать уместные проверки. Commit, push и merge разрешены только по отдельному поручению. Самопроверка агента не заменяет проверку другим человеком.

## Требования и реализация

- Изменение требований сначала отрази в спецификации задачи. Не расширяй объём реализации молча; противоречия с PRD или поручением явно вынеси на согласование.
- План команды не объявляй утверждёнными заказчиком критериями. Эксперимент, прототип и работающая интеграция — разные результаты.
- Не объявляй непроверенную интеграцию работающей. Для вывода укажи версию агента, условия, проверенные сценарии, фактический результат и ограничения.
- Опасные сценарии проверяй только в изолированной среде с тестовыми данными. Не используй рабочие файлы, базы и удалённые репозитории как мишень теста.
- Не раскрывай токены, секреты и данные авторизации в файлах, командах отчёта или ответах.

## Завершение задачи

Сообщи, какие файлы изменены, что проверено и с каким результатом. Отдельно перечисли непроверенное, ограничения, открытые вопросы и обнаруженные расхождения с исходниками. Для кода используй уместные автотесты; для исследования или документации опиши проверку источников и критериев без бессмысленных автотестов.
