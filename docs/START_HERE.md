# С чего начать работу над Agent Guard

Agent Guard помогает новичку понять опасное действие coding-агента до выполнения и разрешить его один раз либо отказать. Разрабатываем локальный MCP-сервер: общее ядро проверяет действие, отдельная LLM объясняет последствия, исполнитель запускает только подтверждённую команду. Первую интеграцию проверяем на OpenCode; наличие MCP само по себе не закрывает обходы через другие инструменты.

## Порядок работы

1. Прочти спринт: S02 идёт 24–27.11.2026, Демо 2 — 28.11.2026. Эти сроки заменяют старый календарь. Прогоны 007 переданы Александру, ревью — Алексею.
2. Найди свою спецификацию и прочти её границы и критерии приёмки.
3. Проверь результаты зависимостей и принятые решения. О блокере сообщи Алексею; независимую часть продолжай.
4. Выполни задачу в её границах. Требования сначала меняй в спецификации. Опасные опыты — только на тестовых данных.
5. Проверь критерии: для кода — уместные тесты; для исследования — источники и воспроизводимые опыты. Заглушка не подтверждает реальную интеграцию.
6. Передай результат назначенному ревьюеру — другому человеку.

S02 — удаление тестового файла с реальной LLM, подтверждением и проверкой обходов. Другие агенты, постоянные разрешения, калибровка и публикация npm перенесены; Ollama — при наличии времени. Полный объём — в спринте.

## Git и передача на ревью

Ветка задачи от `dev`: `features/<имя>/<номер>-<спецификация>`. Проверь ветку и незакоммиченные файлы; чужие изменения сохраняй. После ревью изменения направляются в `dev`, по завершении итерации — в `main`. Проверяет другой человек, назначенный в спецификации с учётом спринта. Агент делает commit, push и merge только по отдельному поручению.

Ревьюеру передай результат и список файлов, проверки с ожидаемыми и фактическими исходами, инструкцию воспроизведения с версиями и тестовыми данными, ограничения и открытые вопросы. Секреты не включай; непроверенное обозначай явно.

## Как поручить задачу coding-агенту

Укажи **одну спецификацию**, ветку, профиль роли, результаты зависимостей, разрешённые файлы и границы. Например: «Выполни `specs/005-llm-client.md` по профилю разработчика и принятому контракту 003; меняй только файлы задачи, проверь критерии, перечисли непроверенное; без commit/push/merge». Нет принятого контракта — сначала сообщи о блокере.
