# Проверки перед реализацией 003

Это исследовательские примеры по 001, не реализация ядра, LLM-клиента
или исполнителя Agent Guard. Источник задачи: [001](../../../specs/001-opencode-research.md).
Передача результатов: [003](../../../specs/003-contract-and-core.md).

## Что проверено

27.11.2026 на macOS, Node.js v24.21.0, OpenCode CLI v2.4.2:

- 16 проверок реальных инструментов OpenCode с управляемым локальным
  OpenAI-совместимым тестовым сервером. Он намеренно возвращает конкретный
  tool call, даже если инструмент запрещён. Это не реальная LLM и не
  проверка качества объяснений.
- 10 проверок экспериментального MCP-примера подтверждения с ответами
  тестового клиента. Это не согласие человека и не проверка UI.

Результаты: [results.json](results.json).
Общие условия и ограничения: [отчёт macOS](../opencode-macos-checks.md).

## Файлы и запуск

Требуются установленные OpenCode, Node.js и Python 3; дополнительных
Python/npm-зависимостей у этих скриптов нет. Запускайте из корня репозитория:

```bash
python3 -B docs/research/pre003/run-permission-checks.py
python3 -B docs/research/pre003/check-elicitation-protocol.py
```

Если инструменты не найдены в PATH, задайте `OPENCODE_BIN` и `NODE_EXE`
путями к соответствующим исполняемым файлам. Нужны права на запуск
локального HTTP-сервера и служебные каталоги самого OpenCode.

`run-permission-checks.py` запускает `controlled-model-probe.py` в отдельных
временных папках. Там создаются синтетические файлы, конфигурации,
локальный API на 127.0.0.1 и журналы CLI. Используется фиктивное значение
ключа для локального тестового API; реальный ключ не нужен. Адрес и запросы
не направляются во внешний LLM API. Служебные действия самого OpenCode
могут обращаться к сети. Набор не обещает сетевую/OS-изоляцию.

В контрольных сценариях разрешены запись маркера shell, создание и
редактирование синтетических файлов. В остальных сценариях принудительно
проверяются запреты. Пример MCP из `../opencode-example/mcp-server.js`
запускается под двумя именами: `guard` и `bypass`.

Каждый запуск получает новую временную папку и печатает её путь.
Сводка сохраняется как `suite-results.json`; в подпапках — фактические
конфигурации, каталоги инструментов, `cli.jsonl` и `stderr.txt`.
Канонический путь получается через `resolve()`: на macOS `/var` и
`/private/var` могут обозначать один каталог. Это важно для проверки границ.

`check-elicitation-protocol.py` запускает `elicitation-probe.cjs` с
управляемым JSON-RPC-клиентом. Пример никогда не выполняет команды и
не изменяет показанный целевой файл; пишет только диагностический журнал.
Ответ `allowed_simulation` означает исключительно имитацию разрешения.

## Проверенный профиль ограничений

В тестах разрешения инструментов намеренно широкие, чтобы проверять
жёсткие policies при попытке вызова. Для запретных сценариев добавлено:

```json
{
  "permissions": [
    { "action": "*", "resource": "*", "effect": "allow" },
    { "action": "execute", "resource": "*", "effect": "deny" }
  ],
  "policies": [
    { "action": "tool.use", "resource": "*", "effect": "deny" },
    { "action": "tool.use", "resource": "read:*", "effect": "allow" },
    { "action": "tool.use", "resource": "guard_test_echo:*", "effect": "allow" }
  ]
}
```

Это профиль эксперимента, не готовая конфигурация поставки Agent Guard.
Разрешён только конкретный echo: wildcard на все инструменты MCP-сервера
в данный профиль не добавляется. Policies проверяют permission action,
а не обязательно имя инструмента: например, write/edit используют edit.

Без отдельного `execute: deny` Code Mode может выполнять чистый JS;
после запрета forced-вызов execute возвращает отсутствие инструмента.
Перенос сессии внутри дерева может быть разрешён: отдельно проверено,
что после него запрет shell сохраняется. Перенос за пределы дерева
и чтение внешнего синтетического файла блокируются.

## Ограничение встроенного подтверждения

В отдельном опыте с Big Pickle инструмент `pre003_guard_probe_confirm`
передал `elicitation/create` во время `tools/call`. Клиент объявил
`elicitation.form`, однако ответ не пришёл; соответствующая форма не была
найдена через API списка форм сессии. Через 10 секунд пример вернул
`no_answer`, `executed: false`. Тестовый файл сохранился.

Проверялся headless `opencode run`; работа формы в интерактивном TUI
и действия реального пользователя не проверены. Причина отсутствия
ответа не установлена. Документация и похожий issue не заменяют опыт:

- [OpenCode: MCP input requests](https://opencode.ai/docs/mcp-servers/#input-requests)
- [Issue 51856](https://github.com/anomalyco/opencode/issues/51856) описывает
  похожие симптомы на других версиях; это не доказательство причины на 2.4.2.
- [MCP elicitation 2025-11-25](https://modelcontextprotocol.io/specification/2025-11-25/client/elicitation)
- [Permissions](https://opencode.ai/docs/permissions/) и [policies](https://opencode.ai/docs/policies/).

Для повторения опыта можно подключить `elicitation-probe.cjs` как local
MCP-сервер с `codemode: false`, `protocol: legacy`, разрешить его два
инструмента и запросить `guard_probe_confirm` с `command` и `cwd`.
Список инструментов не содержит отдельного approve-инструмента,
дополнительный аргумент `user_approved` отклоняется.

## Что передаём в 003, 004 и 006

- В 003: вход агента не должен содержать доверенное согласие; внутренний
  actionId создаётся программой. Команда и канонический cwd фиксируются
  до объяснения и подтверждения. Другие/поздние/повторные ответы не
  переносятся на новое действие. Ошибка и отсутствие ответа не разрешают
  выполнение. Это ограничения интерфейса, не доказательство готовой защиты.
- В 004: есть проверенный способ закрывать перечисленные обходы на 2.4.2.
  Потребуется применить и повторить профиль для конечной сборки, включая
  все фактически подключённые плагины/сервисы. Набор не доказывает отсутствие
  всех возможных обходов и не является OS sandbox.
- В 006: approval остаётся отдельным доверенным портом. Встроенная форма
  пока не выбрана как проверенная реализация. Нужен опыт в TUI либо
  отдельный локальный интерфейс по SPRINT.md с полным циклом проверки.

Независимую часть 003 можно реализовывать с явно тестовым approval-портом,
без выполнения команд. Готовность всего защищённого сценария не заявляется.
Точный контракт, правило, поведение неподдерживаемых команд и разрешённый
корень принимает Алексей в спецификации до реализации. 001 целиком не закрыта.
