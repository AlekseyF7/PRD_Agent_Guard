## Фактический результат

Реализован независимый клиент Chat Completions: настраиваемые адрес, модель,
тайм-аут и авторизация; единый системный шаблон; источник ключа через окружение
или внедряемый адаптер; результаты available/unavailable по контракту 003.
Новых runtime-зависимостей нет. Проверенная среда: macOS, Node.js v24.21.0.

- [src/llm/index.ts](../../src/llm/index.ts) — публичный интерфейс.
- client.ts — HTTP, тайм-аут всего вызова, чтение ограниченного ответа и ошибки.
- credentials.ts — источник ключа из выбранной переменной окружения.
- prompt.ts — текущий шаблон agent-guard-explanation-v2; исходный реальный прогон выполнен с v1.
- validation.ts/types.ts — runtime-проверки и интерфейсы.
- [tests/llm.test.ts](../../tests/llm.test.ts) — управляемый транспорт и loopback HTTP.
- [scripts/check-llm.mjs](../../scripts/check-llm.mjs) — ручной безопасный прогон.

Итоговый прогон: **156 тестов, 156 успешных, 0 ошибок и пропусков**:
89 тестов ядра и 67 проверок 005. `npm run check` и `git diff --check` проходят.
Диагностический скрипт дополнительно проверен как дочерний процесс с тестовым
HTTP-сервером и без настроек. Сначала песочница запретила listen (EPERM);
полный прогон выполнен с разрешённым loopback. Это тесты программы, не вызовы
облачной/локальной модели.

**Изменение:** шаблон v2 явно требует условного описания эффекта, различает

о невосстановимости и ограничивает ответ четырьмя короткими пунктами.
Существующий тест CLI сверяет версию с экспортированной PROMPT_VERSION.
Новое правило автоматического «смыслового одобрения» текста не добавляется.

## Облачный прогон Алексея: Groq

Публичная документация: [Chat Completions](https://console.groq.com/docs/api-reference),
[совместимость](https://console.groq.com/docs/openai),
[квоты бесплатного тарифа](https://console.groq.com/docs/rate-limits).
Groq / openai/gpt-oss-20b вернул ответы в прогонах Алексея с v1 и v2.
В повторе v2 исходная ошибка о необратимости не повторилась; подробности
и оставшееся замечание к условной формулировке описаны выше.
API бесплатно только в пределах доступной квоты. При ошибке автоматического
перехода к платному сервису нет.

1. В своей учётной записи [консоли Groq](https://console.groq.com/keys) создать API-ключ.
2. Открыть терминал zsh в корне проекта и задать несекретные настройки:

```sh
export AGENT_GUARD_LLM_BASE_URL='https://api.groq.com/openai/v1'
export AGENT_GUARD_LLM_MODEL='openai/gpt-oss-20b'
export AGENT_GUARD_LLM_AUTH_MODE='apiKey'
export AGENT_GUARD_LLM_TIMEOUT_MS='30000'
```

3. Ввести ключ скрытым вводом. Не вставлять ключ в команду export, файл
   репозитория, чат или скриншот. Следующая команда предназначена для zsh:

```sh
read -rs 'AGENT_GUARD_LLM_API_KEY?Ключ Groq (ввод скрыт): '
printf '\n'
export AGENT_GUARD_LLM_API_KEY
npm run llm:check
unset AGENT_GUARD_LLM_API_KEY
```

Ввод не отображается и не становится текстом команды в истории. Переменная
действует только в текущем терминале и дочерних процессах; это ещё не UI
с сохранением ключа. Удаление переменной не отзывает ключ у провайдера.

Скрипт создаёт временную папку и проверяет синтетический запрос rm -- sample.txt,
но не исполняет его и не читает рабочие файлы. Файл sample.txt даже не создаётся;
модель не должна утверждать, что он существует или что у него есть бэкап.
Вывод: promptVersion, elapsedMs и результат. При unavailable код завершения 1.
Вывод не сохраняется автоматически. Перед передачей результата проверить текст
и не включать ключи. Адрес, модель и условия в отчёт записываются отдельно;
один успешный ответ не доказывает универсальную точность модели.

Пример настроек для библиотечного клиента: [groq.json](../../examples/llm/groq.json).
Диагностический скрипт читает окружение, не этот JSON.

## Локальный прогон Александра

Определить фактический сервер, его версию, model ID Qwen и ОС. Если это Ollama,
сверить [официальный совместимый API](https://docs.ollama.com/api/openai-compatibility).
Другой сервер не объявлять проверенной Ollama. Сервис уже должен быть запущен;
клиент не устанавливает и не запускает его. На ноутбуке Алексея Ollama не нужна.

В своём терминале установить адрес и точный model ID своего локального сервера:

```sh
export AGENT_GUARD_LLM_BASE_URL='http://localhost:11434/v1'
export AGENT_GUARD_LLM_MODEL='REPLACE_WITH_ACTUAL_LOCAL_MODEL_ID'
export AGENT_GUARD_LLM_AUTH_MODE='none'
export AGENT_GUARD_LLM_TIMEOUT_MS='60000'
npm run llm:check
```

Адрес — пример для Ollama, model ID нужно заменить. При none ключ не читается
и Authorization отсутствует. Для локального сервера с авторизацией использовать
apiKey и свой источник ключа; не переносить облачный ключ автоматически.
Пример для библиотечного клиента: [ollama.json](../../examples/llm/ollama.json).

В этот отчёт после опыта добавить сервер/версию, фактический model ID, ОС,
версию промпта, обезличенные настройки, ожидаемый/фактический результат и
ограничения. Внутренние адреса и секреты не публиковать. Если опыта нет —
сохранить «не проверено», не заменять успехом тестового HTTP-сервера.

## Границы результата и оставшиеся критерии

Код не выполняет команды, не разрешает действия и не меняет результат правил.
006 должен вызывать explain только для ask, связывать ответ с ожидающей попыткой
и обрабатывать unavailable. Меню и настоящий системный источник ключей — 004;
полный цикл и безопасная отмена действия — 006; минимум 10 вызовов и метрики — 007.

Реальный вызов и содержательная самопроверка одного ответа v2 записаны выше.
Независимая приёмка Александром и повтор с дополнительными примерами ещё
не выполнены; локальная модель также не проверена.
Наличие слова «объяснение» в успешном ответе API не гарантирует его правильность;
Алексей и Александр должны сверить смысл с синтетическим действием. Устойчивость
модели к prompt injection проверяется на реальной модели отдельно; тест передачи
данных не доказывает полной устойчивости. Поддержка других серверов не заявляется.
