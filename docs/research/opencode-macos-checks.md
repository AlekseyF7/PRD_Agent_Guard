### Повторение без диагностической обёртки

В исходной папке `/private/tmp/agent-guard-lab` старая копия сохранена
как `mcp-server.cd43ca2.js`, а `mcp-server.js` заменён версией a181c6f.
Использован следующий `opencode.json`:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "servers": {
      "guard": {
        "type": "local",
        "command": [
          "/Users/aleksey/.nvm/versions/node/v24.21.0/bin/node",
          "/tmp/agent-guard-lab/mcp-server.js"
        ],
        "codemode": false
      }
    }
  }
}
```

Пути относятся к этой машине; при повторении их нужно адаптировать.
После обновления исходника выполнены:

```bash
cd /private/tmp/agent-guard-lab
opencode reload
opencode mcp list
```

Фактический результат: `Configuration reloaded`, затем
`guard connected`.

### Вызов инструмента моделью

```bash
opencode run --model opencode/big-pickle --agent plan --format json 'Call only guard_test_echo with message macos-a181c6f-check. Do not use any other tools and do not change files. Return the exact tool output.'
```

Команда выполнена из `/private/tmp/agent-guard-lab`.
Ожидался фактический вызов MCP-инструмента, а не только текст модели.
В JSON-потоке CLI получено событие:

```json
{
  "type": "tool_use",
  "tool": "guard_test_echo",
  "status": "completed",
  "input": {"message": "macos-a181c6f-check"},
  "output": "Echo: macos-a181c6f-check"
}
```

Это сокращённое представление полей события; в исходном выводе
`tool` расположен в `part`, остальные поля — в `part.state`.
Затем модель вернула `Echo: macos-a181c6f-check`; CLI завершился с кодом 0.
В этом запуске наблюдался только вызов echo.

Вывод: на macOS с OpenCode v2.4.2 и Big Pickle подтверждены
подключение исправленного сервера, получение каталога и вызов инструмента
моделью. Запреты обходов, доверенное подтверждение, ошибки соединения
и реальное выполнение защищаемой команды этим опытом не проверялись.

## Проверка 3 — данные из 001 для независимой части 003

27.11.2026 подготовлены [воспроизводимые исследовательские примеры](pre003/README.md)
и [сводка результатов](pre003/results.json).

Прямой вызов API `session.permission.create` в тестовой сессии вернул
deny для shell/edit/subagent/external_directory и allow для read/echo.
Отдельно управляемая локальная модель принудительно запросила инструменты
реального OpenCode, чтобы не считать отсутствие попытки доказательством запрета.

| Группа | Фактический результат |
| --- | --- |
| Контроль без запретов: shell/write/edit/другой MCP | Выполнены на синтетических данных |
| Те же shell/write/edit под policies | Blocked by configuration policy; целевые файлы не изменены |
| Делегирование и другой MCP | Forced-вызовы заблокированы |
| Code Mode | Для удаления execute потребовался отдельный permission execute: deny |
| Перенос сессии наружу и внешнее чтение | Заблокированы |
| Перенос внутри дерева, затем shell | Перенос разрешён, последующий shell заблокирован |
| Чтение внутри дерева и Guard echo | Выполнены при действующих запретах |

Итог: 16 успешных проверок ограничений и 10 успешных протокольных
имитаций подтверждения. В имитациях ответы даёт тестовый клиент,
а не человек. Проверены разные исходы, недоверенное согласие из аргумента,
отмена, разрыв stdin, новый actionId, повтор старого ответа и фиксация
параметров действия. Ни одна имитация не исполняет показанную команду.

В реальном headless OpenCode + Big Pickle запрос MCP elicitation завершился
без ответа (no_answer), файл сохранился. Рабочий пользовательский UI
и доверенный сквозной канал согласия не подтверждены. Не переносим
старое утверждение «подтверждение только Desktop»: TUI ещё не проверен.
