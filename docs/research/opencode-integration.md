## Воспроизводимый запуск

Требуются Node.js 24+, OpenCode 2.4.2, локальный доверенный desktop VS Code.
В корне репозитория выполнить npm ci --ignore-scripts и npm run build.
Создать отдельный тестовый проект с sample.txt, не содержащим полезных данных.
Конфигурация Guard находится вне тестового проекта, workspaceRoot — его
канонический абсолютный путь. Пример формата:

```json
{
  "workspaceRoot": "/ABSOLUTE/PATH/TO/TEST/PROJECT",
  "policies": {
    "file_delete": "ask",
    "git_destructive": "block",
    "git_force_push": "block",
    "outside_workspace": "block"
  },
  "llm": {
    "baseURL": "https://api.groq.com/openai/v1",
    "model": "openai/gpt-oss-20b",
    "timeoutMs": 30000,
    "authMode": "apiKey",
    "credentialRef": "AGENT_GUARD_LLM_API_KEY"
  }
}
```

Из корня репозитория:

```sh
npm run guard:opencode -- /ABSOLUTE/PATH/TO/TEST/PROJECT /ABSOLUTE/PATH/TO/guard.json
npm run vscode:package
```

Генератор отказывается перезаписывать opencode.json, .opencode.json или AGENTS.md.
Существующие проекты требуют отдельного согласованного объединения конфигураций;
команда не отключает и не изменяет их глобальные настройки. Секрет генератор
не читает и не записывает. Путь Node фиксируется по текущему process.execPath;
после переноса установки Node профиль нужно актуализировать.

В VS Code: Extensions → ⋯ → Install from VSIX… →
artifacts/agent-guard-panel-0.0.4.vsix → Developer: Reload Window.
Открыть тестовый проект в отдельном окне VS Code, autoOpen оставить включённым.
Затем в его терминале zsh:

```zsh
read -rs 'AGENT_GUARD_LLM_API_KEY?Ключ Groq: '
printf '\n'
export AGENT_GUARD_LLM_API_KEY
opencode --standalone
```

Выбрать модель агента Big Pickle. Это отдельная модель от объясняющей Groq.
Отправить обычную задачу: «Удали sample.txt в текущем проекте».
Проверить, что вызван Guard и в панели показаны точная команда, папка и объяснение.
До решения файл должен сохраняться. Сначала отказать и проверить сохранность;
после нового запроса разрешить один раз и проверить удаление. Повторить на заново
созданном тестовом файле: требуется новое решение. Не создавать его через
обходной инструмент агента. Закрытие панели во время ожидания должно отменять
попытку. Сохранять фактические actionId, результаты и состояние файла без ключей.

Если панель не открылась: Agent Guard: выбрать сервер для тестового проекта.
Это запасной путь, а автоматическое открытие в этом случае считать непроверенным.
После работы выйти из OpenCode, выполнить unset AGENT_GUARD_LLM_API_KEY.
Флаг --standalone выбирает отдельный сервер; он нужен для воспроизводимого
наследования окружения текущего терминала вместо ранее запущенного сервиса.

### Обновление и первый запуск

1. Из корня репозитория выполнить npm run vscode:package, установить
   artifacts/agent-guard-panel-0.0.4.vsix через Install from VSIX… и Reload Window.
2. Завершить старый OpenCode и запустить opencode --standalone из тестового проекта.
   Требуется новый MCP-процесс, потому что код сервера тоже обновлён.
3. Нажать «Настройки» в панели либо вызвать Agent Guard: настройки. При первом
   обнаружении нового проекта предлагается настроить Guard уведомлением.
4. «Проверить хранилище» записывает, читает и удаляет случайный тестовый секрет.
   Это встроенный способ проверить настоящий SecretStorage на целевой ОС.
5. «Подключение LLM»: адрес https://api.groq.com/openai/v1, модель
   openai/gpt-oss-20b, timeout 30000 мс, «Ввести новый API-ключ». Ввод скрыт,
   сохранённое значение обратно в поле не подставляется. Выбрать
   «Проверить подключение»: должна появиться информация об успешном объяснении
   без запуска команды. При ошибке показывается безопасная причина.
6. Завершить OpenCode. В терминале выполнить unset AGENT_GUARD_LLM_API_KEY и
   снова opencode --standalone. Проверить подключение из меню и обычную задачу:
   ключ должен загрузиться из SecretStorage без ввода в терминале.

Если выбран источник «Переменная окружения», он должен быть задан до запуска
OpenCode; этот режим не сохраняет сам ключ. Для LM Studio: адрес сервера Саши,
реальный идентификатор загруженной модели, «Без ключа» при выключенной
авторизации LM Studio. Это настройка подключения, не установка модели.
При включённой авторизации выбрать API-ключ. После смены адреса старый ключ
автоматически не выбирается. Для источника окружения требуется явное согласие
на повторное использование той же переменной у нового адреса.

### Политики

Пункт «Политики автоблокировки» показывает четыре реализованные категории:
удаление, разрушительные Git-операции, force push и известные цели вне проекта.
Нажатие переключает block/ask; отдельный пункт «Сохранить» применяет изменения.
Отмена меню ничего не меняет. Режим остаётся Paranoid: снятие блока означает
запрос решения, а не автопропуск. Полную защиту чтения ключей меню не обещает.

Проверка: запустить запрос на удаление синтетического файла, во время ожидания
сохранить file_delete=block. Старое действие должно получить отмену; его старое
разрешение не принимается. Новый запрос должен сразу вернуть POLICY_BLOCK,
без объяснения и кнопки разрешения. Затем вернуть ask и повторить ручной
разрешение/отказ. Во время исполнения команды изменение настроек отклоняется.
Неверные значения и ошибка сохранения не меняют действующую политику.

### Ключи и хранение

SecretStorage — API VS Code для зашифрованных секретов, с платформенной
реализацией и без синхронизации между машинами (контракт установленного
@types/vscode, interface SecretStorage). Это не собственный файл с паролем.
В коде используются context.secrets.store/get/delete. Реальная проверка
этого адаптера на macOS/Windows остаётся ручной; mock не доказывает ОС-хранилище.

Несекретные значения сохраняются атомарно по хэшу канонического workspaceRoot:

- macOS: ~/.config/agent-guard/settings/<sha256>.json;
- Windows: %LOCALAPPDATA%/AgentGuard/settings/<sha256>.json.

В JSON находятся policies, baseURL, model, timeoutMs, authMode и credentialRef.
Ключа в нём нет. Bootstrap guard.json остаётся источником рабочего каталога
и лимитов; сохранённые policies/llm проекта загружаются поверх него при старте.
Некорректный сохранённый файл вызывает ошибку старта, не молчаливый сброс защиты.

В Webview ключ не передаётся: password Input Box работает в extension host.
Host загружает ключ по credentialRef и передаёт его авторизованному loopback API
выбранного сервера только в память. Это не MCP-инструмент. После перезапуска
сервера он запрашивает повторную загрузку; при недоступности VS Code/хранилища
объяснение недоступно, автоматического согласия нет. Переход на none не читает
старый ключ и не добавляет Authorization. Новые настройки отменяют pending.

Проверить замену ключа, удаление выбранного ключа и ошибку подключения после
удаления. При ошибке хранилища открытый JSON не используется как запасной способ.
Другие уже запущенные MCP-экземпляры проекта нужно перезапустить: меню меняет
выбранный экземпляр и настройки следующих запусков, а не рассылает изменение
во все процессы. Доступ программ того же пользователя и корпоративная
неизменяемость политик этой реализацией не обеспечиваются.

### История

В панели раскрыть «История сессии». Показаны последние 50 завершённых попыток
выбранного MCP-процесса, новые сверху: время, команда, папка, объяснение,
полученное решение и результат. Блокировки/отказы/отмены входят, BUSY не входит.
После остановки процесса история исчезает. Она не пишется в JSON или журнал.

Для ограничения памяти команда сокращается до 8192 символов, объяснение
и каждый поток вывода — до 4096 символов; сокращение явно обозначено.
Настоящий результат исполнения сохраняет свои прежние лимиты 64 KiB на поток.
Из истории нельзя разрешить или повторно выполнить команду. Она загружается
отдельно при раскрытии и изменении счётчика, не передаётся целиком при каждом
state polling. Это частичная история сессии, не постоянный аудит-лог PRD.
