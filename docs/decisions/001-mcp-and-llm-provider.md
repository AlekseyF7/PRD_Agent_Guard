# ADR-001: MCP-сервер и настраиваемое подключение LLM

Дата: 2026-11-15
Статус: принято

## Задача

Agent Guard должен проверять опасные действия coding-агента
до выполнения, объяснять последствия через LLM и получать
подтверждение пользователя.

Нужна общая реализация для подключения к разным агентам.

## Решение

### MCP как основа интеграции

Реализуем Agent Guard как локальный MCP-сервер.

Он предоставляет собственные инструменты выполнения команд
и изменения файлов. Общее ядро проверяет действия, получает
объяснение от LLM и обрабатывает решение пользователя.

Первый поддерживаемый агент — OpenCode.
GigaCode и другие агенты рассматриваются после проверки OpenCode.

### Обязательная проверка

В поддерживаемой конфигурации агента необходимо запретить
альтернативные инструменты выполнения команд и изменения файлов.

MCP сам по себе не перехватывает встроенные инструменты агента.

Возможность исключить обход Agent Guard необходимо подтвердить
экспериментом на конкретной версии каждого агента.

### Объяснения через LLM

Используем готовые модели через OpenAI-совместимый API.

Пользователь может подключить:
- облачный API;
- локальную Ollama;
- другой сервер с совместимым API.

Параметры подключения: baseURL, model, apiKey, timeoutMs.

API-ключ передаётся через переменную окружения.
Ключи не включаются в репозиторий или распространяемый пакет.

Отдельную модель не обучаем. Docker не обязателен.

### Поставка

Планируем распространять MCP-сервер через npm.
Пользователь добавляет команду запуска в MCP-настройки агента
и настраивает подключение LLM.

## Причины выбора

- Общее ядро и MCP-инструменты можно использовать с разными агентами.
- Не требуется отдельный нативный плагин для каждого агента,
  если MCP и настройки клиента обеспечивают нужное поведение.
- Пользователь выбирает облачную или локальную модель.
- Первую версию можно запускать без собственной облачной инфраструктуры.

## Ограничения

- Обязательность проверки зависит от настроек и возможностей агента.
- Поддержка MCP не означает автоматическую совместимость всех функций.
- Способ подтверждения пользователем требует проверки в каждом клиенте.
- Облачные модели могут требовать оплаты.
- Скорость локальных моделей зависит от оборудования.
- Единый формат API не гарантирует одинаковое качество моделей.

## Условия подтверждения архитектуры

На OpenCode необходимо проверить:
1. Подключение и вызов нашего MCP-инструмента.
2. Запрет встроенных и иных обходных инструментов.
3. Получение объяснения от настроенной модели.
4. Показ объяснения и получение решения пользователя.
5. Выполнение только подтверждённого действия.
6. Отсутствие выполнения при отказе или ошибке.

Принятие архитектуры не означает, что эти возможности уже проверены.
