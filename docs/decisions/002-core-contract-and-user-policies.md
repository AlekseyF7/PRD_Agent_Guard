# ADR-002: контракт ядра и пользовательские политики

Дата: 27.11.2026. Решение команды принято Алексеем в обсуждении контракта 003.
Это изменение плана команды, а не новое согласование с заказчиком и не отчёт о реализации.
Уточняет [ADR-001](001-mcp-and-llm-provider.md); точный контракт — в
[003](../../specs/003-contract-and-core.md).

## Принято

- Расширяемое независимое ядро с несколькими правилами риска вместо белого
  списка одной демонстрационной команды. Первый набор: удаление через `rm`,
  разрушительные операции Git, принудительный push, выход за рабочую область.
  Полнота анализа произвольного shell не обещается.
- Результаты проверки: `allow`, `ask`, `block`. Первый режим — **Paranoid**:
  корректные незапрещённые команды получают `ask`, включая `ls` и неизвестные
  команды. `allow` зарезервирован для будущего режима **Fast**.
- Сначала валидация и политики автоблокировки. При `block` — причина,
  без вызова LLM и кнопки разрешения. При `ask` — объяснение и решение человека.
  Отключение автоблокировки переводит распознанную категорию в `ask`.
- Меню выбора политик при первом подключении и возможность открыть настройки
  повторно пытаемся реализовать к Демо 2 в 004. JSON-файл — сохранение выбора
  меню, не обязательное ручное редактирование пользователем. Ядро получает
  уже проверенные настройки; формат определяет 003. Не проводим входной тест знаний.
- Ошибка, тайм-аут или пустой ответ LLM: предупреждение «Объяснение недоступно»
  и явное «Разрешить один раз без объяснения» либо «Отказать» для любого
  корректного незаблокированного действия. Наличие статического объяснения
  не является условием такого разрешения; база готовых объяснений не нужна.
  Пока LLM отвечает, показываем ожидание. Ошибка не выдаёт разрешение автоматически.
- При полученном объяснении: «Разрешить один раз» и «Отказать».
  Отсутствие ответа человека и ошибка канала подтверждения означают отсутствие исполнения.
- Решение привязано к неизменяемым команде, канонической папке и новому
  идентификатору попытки. Изменение параметров требует нового цикла.

## После первого объёма

Fast с автопропуском, постоянное разрешение изменений конкретного файла,
настройки подробности объяснений — последующее развитие.
Обязательные корпоративные политики с источником, который нельзя изменить
обычному пользователю или агенту, — после MVP. Пользовательский JSON сам
по себе такой защиты не даёт. Защита чтения секретов также требует отдельной
проверки путей чтения; тумблер без реализации не объявляется защитой.

## Влияние на план и проверку

003 включает контракт, код ядра и автотесты; принятие этого решения закрывает
обсуждение контракта, но не всю задачу. 004 отвечает за меню и доверенный UI,
005 — за объяснение или его явную недоступность, 006 — за связь этапов и исполнение,
007 — за проверку обычного и деградированного сценариев, 008 — за честный показ.
Меню — новая цель к Демо 2; при нехватке времени перенос фиксируем отдельно,
не объявляем ручной конфиг выполненным меню.

На OpenCode v2.4.2 есть [результаты технических опытов](../research/pre003/README.md),
но доверенное подтверждение в настоящем UI ещё не подтверждено. Это блокер
полного сценария, а не независимой реализации ядра с тестовыми зависимостями.
Успешный деградированный сценарий не заменяет требование показать реальное
объяснение LLM. Автоблокировка действует в пределах распознанных форм команд;
проверка папки не является изоляцией файловой системы средствами ОС.
