# Agent Guard

Agent Guard — защита от опасных действий coding-агентов: проверка до выполнения, объяснение последствий через LLM и явное подтверждение пользователя. Аудитория — новички, студенты и начинающие разработчики.

## Архитектура

Принятое командой направление — локальный MCP-сервер с общим ядром проверки и собственными инструментами выполнения команд и изменения файлов. Первую интеграцию проверяем на OpenCode. Для обязательной проверки необходимо исключить выполнение защищаемых операций через другие доступные агенту инструменты. MCP сам по себе их не перехватывает; работоспособность ограничений ещё предстоит подтвердить экспериментом.

Объяснения получаем от готовой LLM через OpenAI-совместимый API. Пользователь настраивает `baseURL`, `model`, ключ через переменную окружения и `timeoutMs`. Можно подключить облачный сервис или локальный сервер, например Ollama. Docker необязателен. Ответ LLM не отменяет запрет правил. При отказе пользователя или отсутствии подтверждения действие не выполняется. Если LLM недоступна, для незаблокированного действия пользователь может явно выбрать «Разрешить один раз без объяснения». Ошибка сама ничего не разрешает.

[Контракт и политики](docs/decisions/002-core-contract-and-user-policies.md): сначала автоблокировка по выбранным правилам, затем объяснение и подтверждение. В первом режиме Paranoid все незаблокированные команды требуют решения; Fast и постоянные разрешения отложены. Меню политик — цель к Демо 2, реализация и проверка ещё требуются.

Планируем распространять MCP-сервер через npm. Подключение GigaCode и других агентов зависит от результатов отдельного исследования. Установочного пакета и подтверждённых интеграций этот план не заявляет.

## Планирование

- [BACKLOG.md](BACKLOG.md) — единый список спецификаций по итерациям: описание, один исполнитель, отдельный ревьюер, критерии оценки. Без статусов.
- [SPRINT.md](SPRINT.md) — цель текущей недели и выбранные номера спецификаций. Без дублирования требований и статусов.
- [specs/TEMPLATE.md](specs/TEMPLATE.md) — шаблон подробной спецификации. Создаётся и согласуется до реализации.

Алексей в начале недели выбирает объём с учётом доступности участников. В конце недели команда показывает результат, сверяет критерии и решает, что переносить. Затем `SPRINT.md` заменяется планом следующей недели; история остаётся в Git. Статусы обсуждаем на командных встречах.

Одна спецификация — один ответственный исполнитель. Совместное обсуждение разрешено; ревью выполняет другой участник. Если работа требует двух независимых результатов от разных людей, создаём две спецификации. Карточки будущих задач не означают, что подробные спецификации уже написаны.

## MCP и подтверждение 006

Сервер предоставляет `guard_execute_command`, показывает действие в отдельной
панели Agent Guard и исполняет его только после разового решения пользователя.
Первая версия обрабатывает одну попытку за раз; остальные получают BUSY.

После сборки `npm run guard:check -- /absolute/path/config.json` запускает
безопасную ручную проверку. Панель VS Code собирается через
`npm run vscode:package` и устанавливается из локального VSIX; браузерный
вариант доступен командой `npm run guard:panel -- PID`. Проверка сохраняет
сессию до `q`, Enter создаёт новый запрос без повторного открытия панели. [Настройка, проверенные сценарии и ограничения](docs/research/mcp-execution-checks.md).
Браузерные разрешение/отказ проверены Алексеем. Реальные Windows, установка
VS Code-панели и агентные интеграции ещё требуют проверки;
наличие MCP не означает перехват всех инструментов агента.
