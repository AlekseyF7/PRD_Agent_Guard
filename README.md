# Agent Guard

Agent Guard — защита от опасных действий coding-агентов: проверка до выполнения, объяснение последствий через LLM и явное подтверждение пользователя. Аудитория — новички, студенты и начинающие разработчики.

## Архитектура

Принятое командой направление — локальный MCP-сервер с общим ядром проверки и собственными инструментами выполнения команд и изменения файлов. Первую интеграцию проверяем на OpenCode. Для обязательной проверки необходимо исключить выполнение защищаемых операций через другие доступные агенту инструменты. MCP сам по себе их не перехватывает; работоспособность ограничений ещё предстоит подтвердить экспериментом.

Объяснения получаем от готовой LLM через OpenAI-совместимый API. Пользователь настраивает `baseURL`, `model`, ключ через переменную окружения и `timeoutMs`. Можно подключить облачный сервис или локальный сервер, например Ollama. Docker необязателен. Ответ LLM не отменяет запрет правил. При отказе пользователя, отсутствии подтверждения или ошибке объяснения действие в первой версии не выполняется.

Планируем распространять MCP-сервер через npm. Подключение GigaCode и других агентов зависит от результатов отдельного исследования. Установочного пакета и подтверждённых интеграций этот план не заявляет.

## Планирование

- [BACKLOG.md](BACKLOG.md) — единый список спецификаций по итерациям: описание, один исполнитель, отдельный ревьюер, критерии оценки. Без статусов.
- [SPRINT.md](SPRINT.md) — цель текущей недели и выбранные номера спецификаций. Без дублирования требований и статусов.
- [specs/TEMPLATE.md](specs/TEMPLATE.md) — шаблон подробной спецификации. Создаётся и согласуется до реализации.

Алексей в начале недели выбирает объём с учётом доступности участников. В конце недели команда показывает результат, сверяет критерии и решает, что переносить. Затем `SPRINT.md` заменяется планом следующей недели; история остаётся в Git. Статусы обсуждаем на командных встречах.

Одна спецификация — один ответственный исполнитель. Совместное обсуждение разрешено; ревью выполняет другой участник. Если работа требует двух независимых результатов от разных людей, создаём две спецификации. Карточки будущих задач не означают, что подробные спецификации уже написаны.
